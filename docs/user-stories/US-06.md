# US-06：部署到 Vercel 與整體驗收

## User Story

**作為** 開發者，
**我想** 將應用程式部署到 Vercel 並在公開網址上跑完整個核心流程，
**這樣** 我才能確認產品不是只有在本地機器上能跑。

## Acceptance Criteria

- [ ] AC1：所有環境變數在 Vercel 專案設定中正確配置（Supabase、Telegram）。
- [ ] AC2：`npm run build` 在本地通過後，部署至 Vercel 成功。
- [ ] AC3：部署後在公開網址可完成整條流程：
  - 輸入 `2330.TW` 查詢股價 → 顯示成功
  - 輸入目標價並儲存追蹤 → 資料寫入 Supabase
  - 回到頁面確認追蹤清單顯示
  - 前端輪詢約每 60 秒更新一次
  - 股價達標時收到 Telegram 通知
  - `is_notified` 正確更新且不重複通知
- [ ] AC4：部署版本與本機版本行為一致，無 regression。

## Technical Notes

- **Vercel 環境變數設定**：
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `TELEGRAM_BOT_TOKEN`
  - `TELEGRAM_CHAT_ID`
- **部署指令**：`vercel --prod` 或透過 GitHub 整合自動部署
- **驗收注意**：某些行為在 production 與 local 可能不同：
  - Serverless function 首次啟動可能較慢（cold start）
  - 前端輪詢在 production 的表現須實際確認
- **回退方案**：若 production 發現問題，可快速回到最後一個穩定 Commit 重新部署

## Design Reference

設計稿：`docs/design.pen`「股價看板」Frame

### 部署後 UI 檢查重點

| 項目 | 檢查方式 |
|---|---|
| 設計圖佈局是否正確渲染 | 比對 production URL 畫面與設計圖的 header / formCard / resultCard / wlSection 佈局 |
| 字體（Inter）是否載入 | Google Fonts / next/font 在 production 是否正常 |
| 淺色／深色主題切換 | 確保 `$--background` / `$--card` 等 CSS variables 在 production 正確套用（若已有實作） |
| 圖表 Recharts 渲染 | Server-side rendering 相容性確認（使用 `dynamic import` + `ssr: false` 若遇到 hydration 問題） |

### 環境變數對應設計稿

設計稿使用 `$--` 前綴的 CSS variables（見 `_dependency-and-tech-notes.md` 的 Design Tokens 對照表），這些變數在 production 須確保 Tailwind config 或 CSS variables 有正確載入。

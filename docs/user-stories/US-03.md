# US-03：追蹤清單顯示與自動更新

## 與 spec 範圍

本 US 涵蓋 `docs/spec.md` §4 **必做**之前端輪詢：固定 60 秒、**股價結果區（若有）與追蹤清單每一筆**皆刷新、單筆失敗不拖垮整頁、卸載時停止排程。**清單內 sparkline** 為 §4「最好有」，可先做佔位，完整圖形見 **US-05**。

## User Story

**作為** 使用者，
**我想** 看到我已儲存的追蹤股票清單，且系統會自動更新股價，
**這樣** 我就不用手動一筆一筆查詢。

## Acceptance Criteria

- [x] AC1：頁面載入時從 Supabase 讀取 `watchlist` 全部資料。
- [x] AC2：清單以卡片式佈局顯示，每張卡片包含**股票代號、目標股價、目前股價（若已有）、是否已通知狀態**。
- [x] AC3：追蹤清單為空時，顯示空狀態提示（例如「尚未加入任何追蹤項目」），而非空白畫面。
- [x] AC4：資料讀取中時，顯示載入狀態。
- [x] AC5：讀取失敗時，畫面顯示繁體中文錯誤訊息。
- [x] AC6：**新增追蹤項目後，清單自動更新**（不需手動重整頁面）。
- [x] AC7：**前端輪詢每 60 秒觸發一次**，重新取得清單內**每一筆**股票的最新股價並更新 UI。
  - 含股價結果區（若目前有顯示查詢結果）與追蹤清單內全部卡片。
  - 單一股票查價失敗時，其餘股票與整頁仍維持可用。
- [x] AC8：頁面離開或元件卸載時，停止輪詢（避免資源洩漏）。
- [x] AC9：**必做（spec §7、§9）** 每一輪輪詢中，對**成功取得報價**的追蹤列，須將 **`last_price` 寫入 Supabase** `watchlist`（若有使用 `updated_at` 亦應一併更新）。**不可**僅更新前端 state 而資料庫長期為空，導致 US-04 無法正確比對。實作上通常與 **US-04** 共用同一支 server API（查價 → 寫入 `last_price` → 達標則發 Telegram）；若拆為兩步，仍須保證同一輪內 DB 與畫面一致。

## Technical Notes

- **輪詢實作**：建議使用 `useWatchlistPolling` custom hook，內部使用 `setInterval(60000)`，onCleanup 清除
- **輪詢刷新範圍**：每一輪須同時更新：
  1. 股價結果區（若目前仍顯示有效查詢結果）— 報價與 **走勢圖所需 chartData**（若已實作 US-05）
  2. 追蹤清單內每筆卡片之價格與更新時間，且 **Supabase `last_price` 須一併更新**（AC9）
- **容錯設計**：迴圈遍歷每筆 `symbol` 個別查價，`Promise.allSettled` 確保單筆失敗不影響其他
- **與 US-04 分工**：達標 **Telegram** 與 `is_notified`／`notified_at` 由 US-04 負責；**`last_price` 持久化**須在本輪詢流程中完成（AC9），無論是否達標。
- **UI 互動層**：徽章因通知而切換的細節見 US-04；本 US 可先顯示追蹤狀態與 **`last_price` 來自 DB／本輪刷新** 一致。
- **建議檔案**：
  - `hooks/useWatchlistPolling.ts`（輪詢邏輯）
  - `components/WatchlistCard.tsx`（單張卡片）
  - `components/WatchlistSection.tsx`（清單區塊，含空/載入/錯誤狀態）

## Design Reference

設計稿：`docs/design.pen`「股價看板」Frame

### 本 US 涵蓋的 UI 區塊

| 區塊 | 設計圖節點 | 關鍵規格 |
|---|---|---|
| **追蹤清單標題** | `wlHeader` | 標題「追蹤清單」20px bold；副提示可寫「每 60 秒更新」；「sparkline」字樣僅在 **US-05** 上線後有意義，未完成 US-05 可先省略或改為「圖表功能將於加值項目提供」 |
| **追蹤卡片** | `wlCard1` / `wlCard2` | 圓角 16px，`$--card` 底 + `$--border` 描邊，內距 22px，vertical gap 14px |
| **卡片標題列** | `wl1Top` | 股票代號 17px bold（左）+ 刪除按鈕 trash-2 icon（右，本 US 先隱藏或 disabled） |
| **卡片價格列** | `wl1Mid` | 左側「最新價」12px label + 價格 22px bold（`$--primary`）；右側「目標」12px label + 目標價 16px semibold |
| **狀態徽章** | `wl1Tag` | 綠底 pill `$--color-success`，「追蹤中」11px semibold。若 `is_notified = true` 則改為「已達標通知」 |
| **空狀態** | （設計圖未繪製，需自行實作） | 建議置中文字「尚未加入任何追蹤項目」搭配 `$--muted-foreground` |

### 佈局層級

```
wlSection
  └── wlHeader（標題列）
  └── wlGrid (horizontal gap 16px)
       ├── wlCard1
       │    ├── wl1Top（代號 + 刪除）
       │    ├── wl1Mid（最新價 + 目標）
       │    └── wl1Badge（狀態徽章）
       └── wlCard2（同結構）
```

### 狀態對應

- **載入中**：wlGrid 內顯示 skeleton 或 loading spinner
- **空清單**：wlGrid 改為空狀態提示文字
- **載入失敗**：errorBanner 顯示錯誤
- **有資料**：wlGrid 內以 flex-wrap 排列卡片
- **輪詢進行中**：不需額外 UI 提示，價格數字自動更新即可
- **單筆查價失敗**：該卡片的價格顯示「—」維持版面，不影響其他卡片

### 設計圖注意

- wlGrid 目前只有 2 張卡片範例，實作時須改為動態列表
- 刪除按鈕在本 US 應先隱藏（留給 US-05），避免混淆 scope
- sparkline 區域在本 US 可先留空或顯示簡易佔位（留給 US-05）

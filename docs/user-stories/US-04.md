# US-04：股價達標 Telegram 通知

## 與 spec 範圍

本 US 涵蓋 `docs/spec.md` §4 **必做**之達標通知、`is_notified`／`notified_at` 更新規則（**僅 Telegram 成功後**才標記），以及不重複通知。觸發時機與 **`last_price` 寫入**須與 **US-03** 輪詢銜接（見 AC1、AC8）。

## User Story

**作為** 使用者，
**我想** 在股票價格達到目標價時收到 Telegram 通知，
**這樣** 我就不用一直盯著畫面。

## Acceptance Criteria

- [ ] AC1：當 **`last_price`（已寫入 DB，見 US-03 AC9）`>= target_price`** 且 `is_notified = false` 時，觸發 Telegram 通知。
- [ ] AC2：通知內容包含**股票代號、目前股價、目標股價、觸發時間**。
- [ ] AC3：Telegram 發送成功後，將 `is_notified` 更新為 `true` 並寫入 `notified_at`。
- [ ] AC4：Telegram 發送失敗時，`is_notified` 維持 `false`，不標記為已通知。
- [ ] AC5：已通知過的項目不重複發送通知。
- [ ] AC6：**必做（spec §4、§11）** 通知發送**失敗**時，須有**可察覺**的處置：**不可**僅 `console` 而使用者完全無感。至少擇一：全域 **errorBanner**（或同等）顯示**繁體中文**提示（例如「達標通知發送失敗，請稍後再試或檢查設定」），或 UI 上標示該筆「待重試通知」狀態；並可輔助 server log。
- [ ] AC7：`TELEGRAM_BOT_TOKEN` 與 `TELEGRAM_CHAT_ID` 從環境變數讀取，不寫死在前端。
- [ ] AC8：與 US-03 同一輪刷新流程中，對每筆成功查價之追蹤列**皆更新** `last_price`（**未達標**亦須更新），再執行達標判斷與通知；避免「只通知不更新」或「只更新有達標的列」。

## Technical Notes

- **Telegram Bot API**：
  - Endpoint：`https://api.telegram.org/bot{TOKEN}/sendMessage`
  - Payload：`{ chat_id, text, parse_mode }`
- **通知範例**（依 spec §8）：

  ```
  股價達標提醒
  股票：2330.TW
  目前股價：2205
  目標股價：2200
  時間：2026-04-29 14:30
  ```

- **發送時機**：依賴 US-03 的輪詢機制。每一輪於 **server**（Route Handler 等）完成：**寫入／更新 `last_price`** → 比對是否達標 → 必要時呼叫 Telegram；順序須符合 spec §9。
- **與 US-03 AC9**：實務上建議 **單一 API**（例如 `POST /api/check-prices`）一次處理「清單內全部 symbol」之查價、寫 DB、通知，客戶端輪詢結尾呼叫該 API，或客戶端先刷新 UI 再由 API 負責持久化—**以 DB 為準**避免分歧。
- **安全性**：Telegram 相關 API 呼叫必須在 **Server 端**（Route Handler / Server Action）執行，Token 不可暴露給客戶端。
- **已通知不重複**：關鍵邏輯在於「通知成功才更新 `is_notified`」，若先更新才發送，發送失敗時通知就永久遺失了。
- **MVP 限制**：`is_notified = true` 後不會自動重置。若價格跌回目標以下再漲回，不會再次通知。此屬已知限制，非 bug。
- **建議檔案**：
  - `app/api/check-prices/route.ts`（觸發比對與通知的 Route Handler）
  - `lib/telegram.ts`（Telegram API 封裝）
  - 擴充 `hooks/useWatchlistPolling.ts`（輪詢結束後觸發 Route Handler）

## Design Reference

設計稿：`docs/design.pen`「股價看板」Frame

### 本 US 涵蓋的 UI 區塊

| 區塊 | 設計圖節點 | 關鍵規格 |
|---|---|---|
| **已達標通知徽章** | `wl2Tag` | 綠底 pill，內容「已達標通知」11px semibold。`$--color-success` 底 + `$--color-success-foreground` 文字 |
| **通知時間副標** | `wl2Sub` | 位於徽章右側，`$--muted-foreground` 11px，顯示通知時間如「2026-05-02 09:41」 |

### 狀態對應

| watchlist 狀態 | UI 呈現（US-04 負責讓這個正確切換） |
|---|---|
| `is_notified = false` | 徽章顯示「追蹤中」 |
| `is_notified = true` | 徽章改為「已達標通知」+ 顯示 `notified_at` 時間 |

### 設計注意

- 本 US 主要為後端邏輯（Telegram API 呼叫、狀態更新），UI 變動僅為徽章文字與時間顯示
- 通知失敗時之使用者提示見 **AC6**（須符合 spec「畫面顯示清楚提示」之最低限度）

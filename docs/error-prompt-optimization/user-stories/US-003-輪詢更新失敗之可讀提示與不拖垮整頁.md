### US-003：輪詢更新失敗之可讀提示與不拖垮整頁

**作為** 使用者  
**我想要** 在背景自動更新股價失敗時，知道資料可能不是最新，且單一股票失敗不影響其他股票與整頁操作  
**以便** 我不會在不知情下依賴過期報價，同時可繼續使用其他功能

**輸入格式**：
- `useWatchlistPolling` 內對 `fetchStockPrice` 的 `try/catch` 與 `Promise.allSettled` 結果：目前主查詢與輪詢失敗多為靜默（`// Silently ignore`）
- 首頁查詢結果區與追蹤清單各筆卡片之現有 UI 结构（sparkline、`last_price` 顯示）

**輸出格式**：
- 不阻斷輪詢節奏（維持固定間隔，見 spec §4）
- 使用者可察覺的**非阻斷**提示：例如頂部次要條、`aria-live` 簡短訊息，或清單內單筆「更新失敗／資料可能過期」badge（擇一或組合，須符合設計與可及性）
- 成功更新後清除對應提示狀態

**驗收條件**：
- [ ] 手動查詢以外之背景更新失敗時，使用者不靠 console 也能察覺「本次更新未完全成功」或「部分項目無法更新」
- [ ] 清單含多筆時，單一 symbol 查價失敗不導致其他列資料被清空或整頁錯誤
- [ ] 主查詢區（當前有 `stockData`）若輪詢更新失敗，保留上一筆成功資料並顯示適當提示（與 spec「韌性」一致）
- [ ] 不為輪詢引入可變間隔或隨錯誤退避（仍符合 spec 固定 60 秒）

**依賴關係**：
- **US-001**（輪詢失敗對外文案與查價失敗映射一致）

**優先級**：P1  
**相關功能**：spec §4 前端輪詢與韌性（單一查價失敗不拖垮整頁）、`hooks/useWatchlistPolling.ts`

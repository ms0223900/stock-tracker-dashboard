### US-001：統一查價與儲存錯誤文案與單一來源

**作為** 使用者  
**我想要** 在股價查詢或儲存追蹤失敗時，看到與產品規格一致的繁中說明，而不是後端英文或技術細節  
**以便** 我知道這是暫時無法取得資料或連線問題，並知道下一步可重試

**輸入格式**：
- Yahoo／proxy API 失敗、無效代號、解析失敗等錯誤來源（見 `lib/yahoo-finance.ts`、`app/api/yahoo-finance/route.ts`）
- Supabase `insert` 錯誤物件（目前 `useWatchlist` 直接拼接 `error.message`）
- 既有 spec 建議句：股價 API 失敗時顯示「目前無法取得股價資料，請稍後再試」（`docs/spec.md`）

**輸出格式**：
- 使用者可讀的錯誤字串（繁中），依錯誤**種類**對應固定文案；必要時可保留「代號無效」與「連線／服務暫時不可用」的區分
- 集中於單一模組或常數表（例如 `lib/messages.ts` 或 `lib/errors.ts`），hook／UI 只引用對應函式或常數，避免各處硬編碼英文

**驗收條件**：
- [ ] 一般網路／HTTP 失敗／無法解析等非「代號錯誤」情境，使用者看到的文案與 spec 一致或同等可讀（至少包含「目前無法取得股價資料，請稍後再試」類指引），不出現未翻譯的 `status 500` 裸字串作為唯一說明
- [ ] Supabase 儲存失敗時，畫面顯示繁中、可理解訊息（可對常見 code 如 `23505` unique violation 給專用句，其餘 fallback 為通用品質句），不直接暴露整段英文 PostgreSQL 訊息為唯一內容
- [ ] `useStockQuery` 對 `err.message` 的顯示經過對應映射或改用 typed error／Result，符合專案「邊界收窄、禁止大圈 any」原則
- [ ] 新增或調整對應單元測試（錯誤碼／字串映射的純函式）

**依賴關係**：
- 無（可與 US-002、US-003 平行；實作時宜先定義常數表再改 hook）

**優先級**：P0  
**相關功能**：spec Yahoo Finance 錯誤句、§11「股價 API…錯誤時畫面顯示清楚提示」、`AGENTS.md` 單一 API 失敗不拖垮整頁

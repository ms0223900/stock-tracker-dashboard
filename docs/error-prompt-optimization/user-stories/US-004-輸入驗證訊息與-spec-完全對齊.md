### US-004：輸入驗證訊息與 spec 完全對齊

**作為** 使用者  
**我想要** 在股票代號格式不符合台股 MVP 規則時，看到 spec 明載的提示語  
**以便** 我直接知道須使用完整代號格式（例如 `2330.TW`），與驗收／教學文件一致

**輸入格式**：
- `docs/spec.md` §5：`2330`、`台積電`、空值等須顯示錯誤；格式為「台股代號加 `.TW`」、第一版不自動補 `.TW`
- `docs/spec.md` §11：代號錯誤提示須為「請輸入完整股票代號，例如 2330.TW」
- 現況 `lib/validation.ts`：`validateSymbol` 註解為「不強制 `XXXX.TW` 結尾」，通過後可能與 spec／US-002 驗收預期不一致

**輸出格式**：
- `validateSymbol` 行為與 spec 一致：空白 → 與 spec 一致之提示；非 `*.TW` 合法台股格式（如純數字 `2330`、缺後綴）→ **同一** spec 句；含中文等非法字元 → 可維持或微調為單一 spec 句（避免兩種案例兩套長文案，若有則須在 spec／US-002 同步更新）
- `validateTargetPrice` 維持「請輸入大於 0 的目標股價」（已與 spec 一致）
- 表單欄位旁 inline 錯誤顯示邏輯不變（僅訊息與判定調整）

**驗收條件**：
- [ ] 輸入 `台積電`、`2330`（無 `.TW`）或空白時，畫面提示與 spec §11 完全一致
- [ ] 輸入合法 `2330.TW` 等格式時通過驗證，可進入查價
- [ ] `lib/validation.ts` 單元測試涵蓋上述邊界案例
- [ ] 若變更驗證規則，同步更新 `docs/init-project-features/user-stories/US-002-實作輸入驗證與錯誤提示.md` 之驗收說明或標記需重驗

**依賴關係**：
- 無（與 US-001 可平行；建議早做，因影響後續錯誤種類區分）

**優先級**：P0  
**相關功能**：spec §5、§11、`lib/validation.ts`、US-002

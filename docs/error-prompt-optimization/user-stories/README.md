# User Stories：錯誤提示優化

本目錄將「錯誤提示優化」拆成可獨立驗收的小任務，對齊 `docs/spec.md` 對於可查性、繁中訊息與單一 API 失敗不拖垮整頁的要求，並補齊目前實作缺口（例如清單載入／刪除無 UI 提示、輪詢靜默失敗、Supabase 英文訊息直出、驗證與 spec 可能不一致）。

---

## US 一覽表

| US | 標題 | 優先級 | 依賴 | 簡要說明 |
|----|------|--------|------|----------|
| **001** | 統一查價與儲存錯誤文案與單一來源 | P0 | 無 | 將 Yahoo／API／Supabase 失敗映射為 spec 級繁中文案，集中常數與測試 |
| **002** | 追蹤清單載入與刪除失敗的可見提示 | P1 | US-001 | `fetch`／`delete` 失敗須有 UI，非僅 console |
| **003** | 輪詢更新失敗之可讀提示與不拖垮整頁 | P1 | US-001 | 背景更新失敗可察覺；單筆失敗不影響他筆；維持固定間隔 |
| **004** | 輸入驗證訊息與 spec 完全對齊 | P0 | 無 | `*.TW` 與 spec §11 提示句、與現況 `validation.ts` 對齊 |

---

## 依賴關係圖

```
US-004 (驗證與 spec 對齊)
US-001 (錯誤文案單一來源)
       │
       ├──→ US-002 (清單載入／刪除提示)
       │
       └──→ US-003 (輪詢失敗提示)
```

---

## 依賴說明

- **US-001** 為所有「後端服務失敗」對外語句的基礎；US-002、US-003 應引用同一套映射，避免同類錯誤在 banner 與卡片出現不同說法。
- **US-002** 依賴 US-001：Supabase 錯誤 code／訊息轉繁中的規則應先定義，再放入清單載入與刪除流程。
- **US-003** 依賴 US-001：輪詢與手動查詢共用查價錯誤語意時，應共用映射（可額外區分「背景更新」用較輕量 copy）。
- **US-004** 與 US-001 無直接程式依賴，但**建議優先完成 US-004**，使「代號無效」與「服務失敗」在產品語意上可分離，US-001 的映射表較清晰。

---

## 建議開發順序（Wave）

| Wave | 內容 | 可平行 |
|------|------|--------|
| **Wave 1** | US-004、US-001 | 兩者可由各開發者平行進行；完成後小型整合測試錯誤路徑 |
| **Wave 2** | US-002、US-003 | 兩者可平行；皆須讀取 US-001 之常數／映射 API |

驗收時請一併確認：`ErrorBanner` 與欄位 inline 錯誤分工仍符合 `app/page.tsx` 註解（驗證錯誤近欄位、API／儲存錯誤顯著區）。

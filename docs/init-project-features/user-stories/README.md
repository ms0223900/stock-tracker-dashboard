## US-001 ~ US-004：前端

| US | 標題 | 依賴 | 說明 |
|----|------|------|------|
| **001** | 實作股價查詢功能與 UI | US-006 | 輸入台股代號查詢目前股價，顯示價格、更新時間、當日高低開與成交量 |
| **002** | 實作輸入驗證與錯誤提示 | — | 檢查代號格式與目標價合理性，顯示 inline 錯誤訊息 |
| **003** | 實作前端每 60 秒自動更新 | US-001, US-008 | 每分鐘自動重新抓取當前股價與追蹤清單價格，不打斷使用者操作 |
| **004** | 實作當日股價走勢折線圖 | US-006, US-001 | 以 Recharts 繪製當日股價折線圖，X 軸為時間、Y 軸為價格 |

## US-005 ~ US-007：後端

| US | 標題 | 依賴 | 說明 |
|----|------|------|------|
| **005** | 初始化 Supabase 資料庫與 watchlist 資料表 | — | 建立 Supabase project、`watchlist` table、client/server/middleware 連線模組 |
| **006** | 建立 Yahoo Finance 股價查詢模組 | — | 封裝 `fetchStockPrice()`，回傳型別 `StockPrice`，框架無關 |
| **007** | 實作股價更新與 Telegram 達標通知 | US-005, US-006, US-008 | 背景檢查 watchlist 價格，觸及目標價則發送 Telegram 通知並更新 DB |

## US-008 ~ US-009：整合

| US | 標題 | 依賴 | 說明 |
|----|------|------|------|
| **008** | 實作追蹤清單的儲存、顯示與刪除 | US-005, US-002 | 前端串接 Supabase，新增／瀏覽／刪除 watchlist 項目 |
| **009** | 部署至 Vercel 並驗收全功能 | US-001 ~ US-008 | 設定環境變數、部署、驗證所有功能正常運作 |

## US-010 ~ US-012：擴充

| US | 標題 | 依賴 | 說明 |
|----|------|------|------|
| **010** | 解析 Yahoo Finance 回傳的幣別資訊 | US-006 | 從 Yahoo Finance API 解析 `currency` 欄位，加入 `StockPrice` 型別 |
| **011** | 實作多幣別價格格式化與顯示 | US-010 | 依幣別顯示對應符號（NT$、$、HK$、¥…），動態調整小數位數 |
| **012** | 追蹤清單支援幣別儲存與顯示 | US-010, US-005, US-008 | DB 新增 `currency` 欄位，儲存與顯示多幣別追蹤項目 |

## 依賴關係圖

```
US-005 (Supabase) ──→ US-008 (追蹤清單) ──→ US-003 (自動更新)
                        ↕                      ↕
US-006 (Yahoo Finance) ───→ US-001 (股價查詢) ──→ US-004 (走勢圖)
    ↕                          ↕
    ├── US-010 (幣別解析) ──→ US-011 (幣別顯示) ──→ US-012 (追蹤清單幣別)
    │
    ↕
US-002 (輸入驗證) ─────────→ US-008 (追蹤清單)
                               ↓
US-007 (Telegram 通知) ←── US-008, US-005, US-006

US-009 (部署驗收) ←── 全部 US
```

### 依賴說明

- **US-005** 與 **US-006** 是基礎建設，無任何依賴，可最先進行。
- **US-002**（輸入驗證）是純前端邏輯，無後端依賴，可與基礎建設並行。
- **US-001**（股價查詢 UI）需等待 **US-006**（Yahoo Finance 模組）完成。
- **US-008**（追蹤清單）需等待 **US-005**（Supabase）與 **US-002**（輸入驗證）。
- **US-003**（自動更新）需等待 **US-001** 與 **US-008** 完成後才能串接。
- **US-004**（走勢圖）需等待 **US-006** 與 **US-001**。
- **US-007**（Telegram 通知）需等待 **US-005**、**US-006**、**US-008** 三者完成。
- **US-009**（部署驗收）須等所有 US 完成後才進行。
- **US-010**（幣別解析）需等待 **US-006**（Yahoo Finance 模組），因為要修改其型別與解析邏輯。
- **US-011**（幣別顯示）需等待 **US-010** 完成才能讀取 `currency` 欄位。
- **US-012**（追蹤清單幣別）需等待 **US-010**（幣別資料來源）、**US-005**（DB migration）、**US-008**（追蹤清單 CRUD 邏輯）。

## 建議開發順序

考量依賴關係與平行開發的可能性，建議按以下順序進行：

```
第一波（可平行開發）
  US-005  ── Supabase 初始化
  US-006  ── Yahoo Finance 模組
  US-002  ── 輸入驗證（純前端）

第二波
  US-001  ── 股價查詢 UI（需 US-006）
  US-008  ── 追蹤清單 CRUD（需 US-005 + US-002）

第三波
  US-004  ── 走勢圖（需 US-006 + US-001）
  US-003  ── 自動更新（需 US-001 + US-008）
  US-007  ── Telegram 通知（需 US-005 + US-006 + US-008）

第四波
  US-010  ── 幣別解析（需 US-006，可與 US-009 平行）
  US-009  ── 部署與驗收（需全部 US-001 ~ US-008）

第五波
  US-011  ── 幣別顯示（需 US-010）
  US-012  ── 追蹤清單幣別（需 US-010 + US-005 + US-008，可與 US-011 平行）
```

### US-002：後端雙向達標判定與獨立通知狀態更新

**作為** 系統
**我想要** 在每次查價後依使用者設定的方向獨立比對並發送通知
**以便** 向上突破與向下跌破可各自觸發且不重複通知

> **交付約束**：本 US 必須與 **US-003** 同一 PR／同一波次交付，不得單獨上線（避免 below 已觸發卻仍送舊版「股價達標」文案）。

**輸入格式**：
- US-001 完成之 DB 欄位與 [`types/watchlist.ts`](../../../types/watchlist.ts)
- 既有 [`lib/run-watchlist-price-check.ts`](../../../lib/run-watchlist-price-check.ts)、`fetchStockPriceServer`、`isAmbiguousPrevCloseSnapshot`
- Telegram／LINE 發送模組（US-003 方向化文案）

**輸出格式**：
- 更新 `runWatchlistPriceCheck()`：每筆 watchlist 對 above／below 各獨立判定，單輪最多兩次通知嘗試
- 同步更新檔內 `WatchlistRow` interface
- [`/api/check-prices`](../../../app/api/check-prices/route.ts) 與 [`/api/cron/check-prices`](../../../app/api/cron/check-prices/route.ts) 行為自動沿用
- API `results` 字串能區分方向與 skip 原因，例如：
  - `2330.TW: notified above ($2205 >= $2200)`
  - `2330.TW: notified below ($2195 <= $2200)`
  - `2330.TW: already notified above, skipped`
  - `2330.TW: below trigger met but Telegram send failed, is_notified_below kept false`

**驗收條件**：
- [ ] 僅 `notify_above=true` 時行為與現有「≥ 目標價」一致
- [ ] `notify_above=false` 時，即使 `price >= target` 也不觸發 above、不更新 `is_notified_above`
- [ ] `notify_below=true` 且 `price <= target` 且 `is_notified_below=false` 時觸發 below 分支
- [ ] `notify_below=false` 時，即使 `price <= target` 也不觸發 below
- [ ] 兩方向啟用時各自只通知一次；一方向已通知不影響另一方向
- [ ] `price === target` 且雙開：同一輪最多兩次通知嘗試，各自獨立判定成功後才更新對應 `is_notified_*`／`notified_at_*`
- [ ] 每方向須 Telegram 成功（＋LINE 若設定）才更新該方向狀態；失敗不標記
- [ ] `isAmbiguousPrevCloseSnapshot` 時沿用既有 `triggerPrice` 語意
- [ ] 單筆查價失敗不拖垮其他筆

**依賴關係**：
- US-001
- US-003（同波次強制一併交付）

**優先級**：P0
**相關功能**：更新與通知流程、LINE/Telegram 整合

### US-003：追蹤卡片備註顯示、更新與刪除

**作為** 使用者
**我想要** 在追蹤清單每張卡片上查看、編輯與清除備註，且僅在確認後才儲存
**以便** 我能記錄追蹤理由，又不會因輪詢或誤觸而意外覆寫筆記

**開發階段**：前端 Wave 2（可先完成 UI 與串接；DB 持久化 E2E 待 US-001）

**輸入格式**：
- `WatchlistItem`（含 `id`、`symbol`、既有價格欄位；`note` 由本 US 擴充型別）
- 使用者於卡片 `textarea` 輸入之備註、「確認更新」「取消」操作
- US-002 之 `validateWatchlistNote`／正規化邏輯

**輸出格式**：

**型別**（[`types/watchlist.ts`](../../../types/watchlist.ts)）：
- `WatchlistItem` 新增 `note: string | null`

**UI**（[`components/WatchlistCard.tsx`](../../../components/WatchlistCard.tsx)）：
- 每張卡片新增備註區（建議於價格區與 sparkline 之間）：
  - 標籤：**備註**
  - 常駐 `<textarea>`（非另開編輯模式）
  - `note` 為空時 placeholder：**尚無備註**
  - 按鈕：**確認更新**、**取消**（還原為上次已儲存值）
  - **無**獨立「刪除備註」按鈕；清空 input 後按「確認更新」= `note = null`
- `textarea` 具 `aria-label`（例如 `{symbol} 備註`）；錯誤訊息與 input 關聯
- 長字串以 `break-words` 避免破版

**邏輯**（[`hooks/useWatchlist.ts`](../../../hooks/useWatchlist.ts)）：
- 新增 `handleUpdateNote(id: string, value: string)`：
  - 呼叫 `validateWatchlistNote`；無效則顯示錯誤、不寫 DB
  - 成功則 `supabase.from("watchlist").update({ note: normalized, updated_at: ISO })`
  - 失敗顯示繁中，例如「備註儲存失敗，請稍後再試」（可附 `error.message`），保留草稿
- `fetchWatchlist`／`select("*")` 映射 `note`（`row.note ?? null`）
- **草稿保護**：該卡片有未「確認更新」之本地變更時，輪詢或 refetch **不覆寫**該卡片 textarea；無草稿時以 DB `note` 同步
- `mergeWatchlistFromDb` 僅合併價格相關欄位，**勿覆寫** `note` 邏輯與草稿狀態衝突

**驗收條件**：

*前端先行（無 US-001 亦可驗）*：
- [x] 每張追蹤卡片顯示備註 `textarea` 與「確認更新」「取消」
- [x] 無備註時 placeholder 為「尚無備註」
- [x] DB／state 有備註時 input 預填該內容
- [x] 修改內容後未按「確認更新」→ 不觸發 `update`（或 DB 不變）
- [x] 按「取消」→ input 還原為上次已儲存值
- [x] 按「確認更新」→ 執行驗證與 `update` 程式路徑；進行中按鈕 disabled
- [x] 超過 500 字按「確認更新」→ 顯示「備註不可超過 500 字」，不寫 DB
- [x] `update` 失敗時畫面有可讀繁中錯誤，textarea 保留草稿
- [x] 60 秒輪詢更新股價時，有未確認草稿的卡片備註不被覆寫
- [x] 無草稿時輪詢 refetch 後 input 與 state 中 `note` 一致

*需 US-001（或 Dashboard 手動加欄）後 E2E 驗*：
- [ ] 重新整理頁面後備註與 DB 一致（spec Scenario 4）
- [ ] 「確認更新」後 DB `note` 為 trim 後字串，`updated_at` 已更新（Scenario 6）
- [ ] 清空 input 並「確認更新」→ DB `note IS NULL`，追蹤列仍存在（Scenario 8）
- [ ] 輪詢僅更新價格時，已儲存備註不變（Scenario 5）

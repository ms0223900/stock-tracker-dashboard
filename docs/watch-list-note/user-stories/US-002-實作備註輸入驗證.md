### US-002：實作備註輸入驗證

**作為** 使用者
**我想要** 系統在我輸入過長或無效的備註時顯示清楚錯誤，且允許不填備註
**以便** 備註欄位好用又不會寫入不合規資料

**開發階段**：前端 Wave 1（無 DB／migration 依賴，可最先實作）

**輸入格式**：
- 使用者輸入之備註字串（含空字串、僅空白、中英文、換行、emoji）
- 規格：[`watchlist-note-crud.md`](../watchlist-note-crud.md) §2 Story A 驗證規則

**輸出格式**：

**驗證模組**（[`lib/validation.ts`](../../../lib/validation.ts)）：
- 新增 `validateWatchlistNote(value: string): ValidationResult`
- 與既有 `validateTargetPrice` 相同回傳型別 `{ valid: boolean; error: string | null }`
- 建議另提供（或於呼叫端實作）`normalizeWatchlistNote(value: string): string | null`：
  - trim 後空字串 → `null`
  - 否則回傳 trim 後字串

**規則**：
- 空字串／僅空白 → `valid: true`（寫入前正規化為 `null`）
- trim 後長度 ≤ **500** 字元（Unicode 字元數，建議 `Array.from(trimmed).length`）
- 超過 500 → `valid: false`，`error: "備註不可超過 500 字"`
- 不限制換行；允許常見標點

**驗收條件**：
- [x] `""` → valid
- [x] `"   "` → valid（正規化後為 `null`）
- [x] 500 字以內（含中英文、換行、emoji）→ valid
- [x] 501 字以上 → invalid，錯誤文案為「備註不可超過 500 字」
- [x] 錯誤文案為繁中，與 spec 一致
- [x] `npm run typecheck` 通過
- [x] US-003、US-004 可 import 並使用此函式

**依賴關係**：
- 無（對齊既有 init-project US-002 驗證風格即可）

**優先級**：P0
**相關功能**：追蹤清單備註 CRUD；輸入驗證（`docs/spec.md` §5 邊界驗證精神）

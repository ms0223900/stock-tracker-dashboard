### US-004：儲存追蹤時支援選填備註

**作為** 使用者
**我想要** 在儲存追蹤項目時可選填備註
**以便** 我在加入追蹤當下就能記錄買進理由或提醒，且不強制一定要填

**開發階段**：前端 Wave 3（insert 串接可先完成；DB 持久化 E2E 待 US-001）

**輸入格式**：
- 已驗證之股票查價結果（`StockPrice`）、目標股價（既有 `targetPrice` 流程）
- 選填備註字串（`saveNote` state）
- US-002 之 `validateWatchlistNote`

**輸出格式**：

**表單 UI**（[`components/StockResultCard.tsx`](../../../components/StockResultCard.tsx)）：
- 目標股價輸入區下方新增選填 **備註** `textarea`
- 不填備註仍可點「儲存目標股價」
- 備註驗證錯誤以 inline 繁中顯示（近欄位，與 `targetPriceError` 分工一致）

**儲存邏輯**（[`hooks/useWatchlist.ts`](../../../hooks/useWatchlist.ts)）：
- 新增 `saveNote` state 與 `onSaveNoteChange`（或等價命名）
- `handleSave(stockData)`：
  - 目標價驗證通過後，若有備註內容則 `validateWatchlistNote`；無效則不 `insert`、顯示錯誤
  - `insert` payload 含 `note`（正規化：全空白 → `null` 或省略）
  - 成功後清空 `saveNote`（與清空 `targetPrice` 一致）並 `fetchWatchlist()`
- 儲存失敗顯示可讀繁中（沿用既有 `saveError` 模式）

**頁面串接**（[`app/page.tsx`](../../../app/page.tsx)）：
- 將 `saveNote`／`saveNoteError`／`onSaveNoteChange` 傳入 `StockResultCard`

**驗收條件**：

*前端先行（無 US-001 亦可驗）*：
- [ ] 股價結果區顯示選填備註 `textarea`，標籤為「備註」
- [ ] 不填備註、目標價有效時可觸發儲存流程（不因備註阻擋）
- [ ] 備註超過 500 字時不 `insert`，顯示「備註不可超過 500 字」
- [ ] 儲存成功後備註輸入框清空
- [ ] 儲存失敗時顯示錯誤提示（非僅 console）

*需 US-001（或 Dashboard 手動加欄）後 E2E 驗*：
- [ ] 不填備註儲存 → DB 該筆 `note IS NULL`（spec Scenario 1）
- [ ] 填「長期持有，等財報」儲存 → DB `note` 為 trim 後字串（Scenario 2）
- [ ] 儲存後追蹤清單卡片 textarea 顯示該備註（需 US-003 已完成）
- [ ] 重新整理後備註仍存在

**依賴關係**：
- US-002（備註驗證）
- 既有 US-008（追蹤清單儲存）
- 建議 US-003 已完成（卡片可顯示 `note`）；可與 US-003 尾段平行開發
- 軟依賴 US-001（DB `note` 欄位，持久化 E2E）

**優先級**：P1
**相關功能**：追蹤清單備註 Create；[`watchlist-note-crud.md`](../watchlist-note-crud.md) Story A、G2 產品決策（可選填、不強制）
